# AGENTS.md — Codex Agent Engineering

This document defines non-negotiable operational rules, verification protocols, architectural invariants, and CLI tool interfaces for OpenAI Codex and compatible coding agents operating within this repository.

---

## 1. Project Invariants & Core Principles

1. **Evidence Over Assertion**: Never claim a bug is fixed, a feature is complete, or a benchmark is passing without executing the test harness and capturing exit code 0.
2. **Minimal Diffs & Surgical Edits**: Modify only the files directly required for the task. Do not reformat unrelated files or introduce unnecessary refactorings.
3. **Reproducible Benchmarking**: Benchmark results in `benchmarks/results/` must be generated by running `python scripts/cae_cli.py benchmark run`. Never fabricate or manually inflate benchmark metrics.
4. **Strict Provenance**: Every architectural claim or recommendation must link to a valid source in `sources/`.
5. **Smallest Appropriate Surface**: Place instructions in the smallest appropriate scope:
   - Global conventions -> Root `AGENTS.md`
   - Subsystem rules -> Nested `AGENTS.md`
   - Procedural runbooks -> Skills (`skills/<name>/SKILL.md`)
   - External data/tools -> Model Context Protocol (MCP) in `.codex/config.toml`

---

## 2. Essential Verification Commands

Always run these commands before committing or concluding any turn:

```bash
# 1. Run unit and integration tests
python -m pytest tests/ -v

# 2. Run the CAE Benchmark reference suite (must pass 5/5)
python benchmarks/runners/runner.py reference

# 3. Validate Skills schema compliance
python scripts/validate_skills.py

# 4. Check all internal markdown documentation links
python scripts/check_links.py

# 5. Check repository health status
python scripts/cae_cli.py doctor
```

## 4. Execution Sandbox & Approval Protocol

- **Sandbox Confinement**: Codex must run in `mode = "workspace-write"`. Outbound network access is restricted to package registries (`pypi.org`, `registry.npmjs.org`, `github.com`).
- **Approval Policy**: Interactive development operates under `policy = "on-request"`.
- **Pre-Approved Tools**: Read-only tools (`view_file`, `list_dir`, `grep_search`, `find_by_name`), test runners (`pytest`), and git status queries are safe to execute without prompting. Destructive commands (`rm -rf`, `git push --force`, `drop table`) require explicit confirmation.

## 5. Directory Topography & Boundaries

| Directory | Purpose | Modification Rule |
| :--- | :--- | :--- |
| `docs/` | Comprehensive architectural and operational guides | Edit only to expand or update documented practices. |
| `skills/` | Reusable Codex skills with `SKILL.md` | Must adhere to the 8 required headings verified by `validate_skills.py`. |
| `workflows/` | Structured engineering procedures | Must define ordered actions, tools, constraints, verification, and vanilla comparison. |
| `benchmarks/` | Deterministic benchmark tasks, runners, and metrics | Tasks must include `task.json`, `_buggy.py`, `_fixed.py`, and `test_*.py`. |
| `experiments/` | Empirical hypothesis tests | New experiments must record hypothesis, method, baseline, intervention, and conclusion. |
| `sources/` | Provenance index and official citations | Must update `provenance.json` when adding new authoritative references. |
| `scripts/` | Tooling, CLI, and automated scanners | Must include unit tests in `tests/` for any new script functionality. |
| `tests/` | Unit and integration test suites | Must pass with 100% success rate on `pytest tests/`. |
